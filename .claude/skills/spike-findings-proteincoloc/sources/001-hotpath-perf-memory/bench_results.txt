ProteinCoLoc hot-path micro-benchmark — measured results
========================================================
Environment: Julia 1.12.6 (Windows). Synthetic Float64 images with ~50% zeros
(simulating post-Otsu masking). Pearson via stdlib Statistics.cor.
Method: warmup once, then best-of-20 wall time via @elapsed, allocations via @allocated.
Run with: julia --startup-file=no bench_hotpath.jl

Interpretation
--------------
1. correlation() is the dominant hot-path win. Eliminating (a) the per-call
   Dict(:pearson=>...) lookup that returns a ::Function (dynamic dispatch inside
   the patch loop), (b) the `vec(collect(view(x,i,j,:,:)))` double allocation per
   patch pair, and (c) the Union{Float64,Missing} working buffers — replaced by a
   single-pass exclude-zero into two reused Float64 buffers — gives 1.7x–6.0x
   runtime and 135x–1900x less allocation. The memory ratio grows as patches get
   smaller/more numerous (more tiny collect() allocations avoided).

2. patch() converting the Array{Union{Float64,Missing},4} to a dense
   Array{Float64,4} is only ~1.1x on its own (and slightly slower at np=32 in the
   naive dense variant). The Union 4D array's true cost is realized DOWNSTREAM:
   collect(view(...)) on a Union array is what allocates in correlation. The
   highest-value move is to FUSE patch+correlation so the 4D array is never
   materialized for the inference path at all.

Caveat: the 'fast' variant fuses exclude-zero into one pass with reused buffers;
Pearson correlation is invariant to the ordering of paired observations, so the
numeric result matches the current path on dense Float64 input. A production
rewrite must preserve the Union/missing semantics where genuine missing values
(not just zeros) can occur.
