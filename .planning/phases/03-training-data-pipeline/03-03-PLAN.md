<objective>
The DATA-02 persistence layer: turn the Wave-2 in-memory generator into a resumable, version-guarded, sharded JLD2 cache. `hashguard.jl` computes a SHA-256 content hash over the data-defining source files PLUS the canonical generating config (D-05) — any code or config change auto-invalidates stale data. `cache.jl` implements atomic `.tmp`+`mv` shard writes, resume-by-skip, the `meta.jld2` manifest, and the column-major schema matching NeuralEstimators' d×K layout (D-04). The `generate.jl` driver orchestrates main-pool sharded generation, the reserved ≥20-stack ADVI holdout from a disjoint key namespace (D-10), and N-parameterized scale-up where adding shards extends the dataset without regeneration (D-06).

Purpose: This is the "reproducible, resumable, version-guarded cache" half of the phase goal. It makes a 50k→200k generation survivable across pauses and crashes, and makes stale-data reuse impossible after a source/config change.
Output: `spike/data/hashguard.jl`, `spike/data/cache.jl`, extended `spike/data/generate.jl` driver, `.gitignore` rule + a tiny committed fixture, SC-2 round-trip/resume/invalidation tests.

HARD CONSTRAINT: all new files under `spike/`; reach `src/` ONLY via `contract.jl`'s read-only `include()`. Never edit `src/` or root manifests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| generator → persistent JLD2 cache | The on-disk cache is NEW persistent state; a half-written shard or a stale-but-reused cache silently corrupts every downstream metric. |
| source/config → cache identity | The content hash is the integrity boundary: it must change iff the data semantics change. |
| holdout namespace → main pool | The reserved ADVI set must be provably excludable; an index collision would contaminate the benchmark. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Tampering | stale-cache silent reuse after a simulator/prior/encode edit | mitigate | D-05 sha256 over source bytes + canonical config; `open_or_invalidate` ERRORs on mismatch; per-file sub-hashes diagnose which source changed |
| T-03-07 | Integrity/Availability | half-written shard on crash/resume | mitigate | Atomic `.tmp`+`mv` write + reopen-integrity-check; resume predicate `isfile && _loads_ok` regenerates only the in-flight shard |
| T-03-08 | Tampering | reserved holdout leaking into a CV fold (index collision) | mitigate | Holdout drawn from XOR-salted `holdout_rng` into a separate `holdout.jld2`, never indexed into the main pool (D-10) |
| T-03-09 | Tampering/EoP | untrusted `.jld2` deserialization (JLD2 reconstructs arbitrary types) | accept | Cache is self-generated + hash-checked; never load third-party `.jld2`. Documented residual (RESEARCH §Security) |
| T-03-SC | Tampering | npm/pip/cargo installs | N/A | No package installs in this plan; deps added + audited in Plan 01 (Julia General registry) |
| — | Spoofing/Repudiation/Info-Disclosure | — | accept | Offline local file generation, no network/auth/secrets — N/A |
