<objective>
Prove, in isolation and before anything is built on top of it, that this package can load at all on a
GitHub-hosted headless runner.

Purpose: `.github/` does not exist in this repository — there is no CI, and SC3 asks for a test that
"fails CI on calibration drift". Research names the headless GLMakie load as the single highest-risk
CI unknown: `src/ProteinCoLoc.jl:28` does `import GLMakie` at module load, so EVERY `using
ProteinCoLoc` on a runner needs OpenGL system libraries plus xvfb before any Julia step. If that is
wrong, the entire CI tier is blocked, and discovering it inside a finished two-tier workflow costs a
rewrite. This plan de-risks it with a throwaway-shaped job whose only assertion is "the package
loads and the co-resolution gate's versions are what the manifest pinned".

Output: `.github/workflows/headless-smoke.yml` and a measured `15-CI-BASELINE.md` the two later
workflows copy their environment recipe from.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted PR contributor -> GitHub Actions runner | Any workflow trigger reachable from a fork executes contributor-controlled repository content |
| third-party action -> runner filesystem and token | `julia-actions/*` and `actions/checkout` run with whatever `permissions` the workflow grants |
| Actions cache -> job filesystem | A poisoned depot cache would be restored into a job that later produces a gate verdict |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-04 | Elevation of Privilege | `.github/workflows/headless-smoke.yml` triggers | mitigate | Workflow-level `permissions: contents: read`; `push`/`workflow_dispatch` only; `pull_request_target` is absent and its absence is asserted by the Task-1 verify command |
| T-15-05 | Tampering | `run:` steps | mitigate | No `${{ github.event.* }}` interpolation into any shell step; asserted by the Task-1 verify command |
| T-15-06 | Tampering | third-party action supply chain | mitigate | Every action pinned to a major tag (`@v4`/`@v3`); SHA-pinning recorded in `15-CI-BASELINE.md` as a pre-v2.0-release hardening item rather than silently skipped |
| T-15-08 | Tampering | `julia-actions/cache@v3` depot cache | mitigate | Default cache scoping (workflow + job) retained; `cache-name` is NOT widened across trust boundaries |
| T-15-03 | Tampering | shipped model artifact substitution | mitigate | The bundle is resolved through `ProteinCoLoc.estimator_for(8)`, whose `_verify_tree_sha1` / `ensure_artifact_installed` path refuses a mismatched tree — never a bare download |
| T-15-14 | Information Disclosure | secrets in logs | accept | The job needs no secret; only the default `GITHUB_TOKEN` scope, reduced to `contents: read` |
| T-15-SC | Tampering | package-manager installs | mitigate | Julia side: `Pkg.instantiate()` on the committed manifest installs pinned tree-hashes and resolves nothing; `Pkg.add`/`Pkg.resolve` are asserted absent. OS side: `apt-get install` of ten Ubuntu-archive packages, the recipe Makie's own CI uses, recorded in `15-CI-BASELINE.md` |
