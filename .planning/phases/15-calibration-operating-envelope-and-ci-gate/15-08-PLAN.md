<!-- Verified this research session. -->

Runner constraints (research §"Pitfall 6"): `ubuntu-latest` GitHub-hosted runners are 4-CORE and jobs
are capped at 6 HOURS. The full 7-axis envelope sweep is ~8.5 h at 32 threads and far longer at 4 —
porting it into CI guarantees a timeout on a job that has already burned hours. What DOES fit is the
reported-scale SBC/coverage arm the amended confirmatory run demonstrates at 30.9 min wall-clock
(SBC M=2000/L=999 + BF + OOD); SBC alone is ~22 min at 32 threads, correspondingly longer at 4 cores,
so the slow tier must set a realistic `timeout-minutes` well under 360 and must NOT matrix over axes.

The reconciled cost model, for setting that timeout honestly:
  t_draw ~= 0.656 s at 32 threads => M = 2000 is ~21.9 min there. At 4 cores expect roughly
  4-6x that for the simulate-dominated part. Size the timeout from the FIRST observed dispatch run,
  and record the derivation in a comment rather than guessing twice.

The invocation shape: `--consts p15_consts.jl` must be explicit (run_gate.jl:47-54), and
`--artifacts-root artifacts/amended_v2` is mandatory because `run_gate`'s default root is the v1 tree.
On a runner there is no in-repo `artifacts/` tree, so the net must be resolved through
`ProteinCoLoc.estimator_for(8)`'s hash-verified three-path resolution and shimmed into the harness
model shape `(estimator = b.npe, θzt = b.θzt, zt = b.zt, ...)` — the same shim `ci_golden.jl` uses
(src/registry.jl:59-67 vs src/amortized/persist.jl:101-102).

Security controls for `workflow_dispatch` inputs (research §"Security Domain"): validate `sweep_m` as
an integer with bounds, pass it through `env:` and read it with `ENV[...]` inside Julia — NEVER
interpolate `${{ inputs.* }}` or `${{ github.event.* }}` into a `run:` shell string.

CI environment recipe: copy verbatim from `15-CI-BASELINE.md` (the observed-green apt list, Julia
`1.12.6`, `Pkg.instantiate()`, the `xvfb-run -a` prefix). Actions pinned: actions/checkout@v4,
julia-actions/setup-julia@v3, julia-actions/cache@v3, actions/upload-artifact@v4.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `workflow_dispatch` input -> job execution | A dispatch input is the only externally-influenced value in this phase; unvalidated it is both an injection surface and an unbounded-compute surface |
| untrusted PR contributor -> runner | The fast tier is reachable from forks via `pull_request` |
| "the gate is green" -> "the gate works" | A gate never observed to fail is indistinguishable from a broken one; that gap is a control failure, not a documentation gap |
