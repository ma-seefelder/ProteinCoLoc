**`spike/p14/fdr.jl`** — AGPL header, guarded includes of `consts.jl` and `posterior.jl`.

- **`p14_bayes_fdr(v::AbstractVector{<:Real}, alpha::Real) -> NamedTuple`.** Validate `0 < alpha < 1`
  and throw an `ArgumentError` naming the function and the observed value. Degenerate branch BEFORE
  the arithmetic: empty `v` returns `(accepted = Int[], k_star = 0, fdp = 0.0, t_star = NaN,
  cost_ratio = NaN, n = 0)`. Otherwise `ord = sortperm(v)`, `sv = v[ord]`,
  `run = cumsum(sv) ./ (1:length(sv))` — the running **MEAN**. `@assert issorted(run)` with a message
  saying the prefix property is asserted, not assumed. `k = findlast(<=(alpha), run)`; `nothing`
  returns the reject-nothing tuple. Otherwise return `(accepted = ord[1:k], k_star = k,
  fdp = run[k], t_star = sv[k], cost_ratio = sv[k]/(1 - sv[k]), n = length(v))`.

  Docstring must state, in these terms: the controlled quantity is `E[FDP | data]`, the **posterior
  expected** false discovery proportion, which is a MEAN by construction; a running MAX would be a
  different and much more conservative rule controlling the per-comparison posterior error
  probability instead; the guarantee is **conditional on the model being right** and is **not** a
  frequentist long-run FDR; and `cost_ratio = t*/(1-t*)` is the implied decision-risk cost ratio,
  reported so the decision-theoretic reading is available to a referee without the implementation
  committing to it (Müller, Parmigiani & Rice 2007). Also state that no package was added — the rule
  is `sortperm` + `cumsum` + `findlast`.

- **`p14_fdr_over_decided(v_decided, alpha; n_total) -> NamedTuple`.** The batch-scope wrapper. It
  takes the null posteriors of the **decided subset only** and a REQUIRED `n_total` keyword, and
  returns the `p14_bayes_fdr` result merged with `(n_total = n_total, n_decided = length(v_decided),
  decided_fraction = length(v_decided)/n_total, fdr_scope = :decided_subset_only)`. Make `n_total` a
  required keyword — not optional — so an FDR number can never be produced without its decided
  fraction. Copy the structural trick from `p13_calibration_meta`, where `auc` is a required keyword
  precisely so a calibration verdict cannot ship without its discrimination number
  (`spike/p13/result.jl:313-315`).

  Docstring must carry the honest claim verbatim in substance: *the posterior expected false
  discovery proportion is controlled at α_FDR **over the DECIDED subset only** — the batch minus
  abstentions. It is not controlled over the whole batch: an abstained item is neither a discovery
  nor a non-discovery and appears in neither the numerator nor the denominator. The guarantee is
  conditional on the model (calibrated posteriors and a correct class prior) and is a posterior
  expectation, not a frequentist long-run rate.* And it must state the ordering rule and its reason:
  **ABSTAIN FIRST, then FDR-sort the survivors** — because the rejection set `R` is a deterministic
  function of the observed data and therefore σ(data)-measurable, so it pulls out of the conditional
  expectation for ANY data-dependent selection; and the reverse order (sort, then abstain from some
  accepted items) leaves the residual accepted set with a running mean that may EXCEED α, because
  removing items changes both numerator and denominator uncontrollably. Label this derivation
  **Assumption A2** and note it is load-bearing and must be stated explicitly in the report rather
  than asserted.
