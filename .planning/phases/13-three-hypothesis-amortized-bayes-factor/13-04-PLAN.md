**Binding rulings this plan implements (do not reopen):**
- **The dominant trap.** `correlation()` calls `_exclude_zero` (`src/colocalization.jl:154-169,
  187-203`), which drops any pixel where *either* channel is 0.0, NaN or missing, and a patch with
  too few survivors becomes `missing`. Zeroing ch2 inside the mask therefore DELETES those pixels
  instead of creating anti-correlation, and the ladder reads flat for a reason that has nothing to
  do with segregation. The strictly-positive background floor is not optional.
- **The rejected alternatives are not implemented.** Displacement of ch2 objects (confounds with the
  Phase-11 registration nuisance) and intensity anti-correlation (circular — it restates the
  simulator's own mechanism) are both out of scope.
- **The mask rule is a frozen, already-shipped choice.** `_calculate_mask(mci)[1]` via
  `Images.otsu_threshold`, computed once from the unmodified ch1. This satisfies D-16's
  "pre-registered segmentation choice" at zero cost. Do not invent a new thresholding rule.
- **The physical segregated anchor is NOT touched.** It is triply unavailable and sits behind the
  `sealed_holdout` anti-snooping seal; `open_sealed_holdout` is never called in this phase. Under the
  amended D-15 the sanctioned real substrate is instead the six committed `test/test_images/` TIFFs,
  ingested by plan 13-15 — which is why this transform must be substrate-agnostic.
- **ONE code path, two substrates.** `P13_ALPHA_SUBSTRATE = (:simulated, :real)`. The interface
  boundary is `Vector{Matrix{Float64}}`, which both `simulate_pair` (`spike/simulator/forward.jl:103`)
  and `load_tiff.(paths)` (`src/LoadImages.jl:433`) already emit. `alpha_segregate` is typed on
  `AbstractMatrix{Float64}` and must know NOTHING about where its input came from. The three
  substrate-dependent knobs — background floor, frame size, and what `alpha = 0` means — belong
  in a provenance record supplied by the caller, never in the algorithm.
- **`all(y_out .> 0)` is FORBIDDEN as an invariant.** It is FALSE on real input at `alpha = 0`, where
  the output IS the input: `positive_c2` carries 2 exact-zero pixels and `negative_c2` carries 3, of
  1 414 528, in the committed source files. Asserting it costs a red Wave-0 suite on a correct
  algorithm. The locked rule is `P13_ALPHA_ZERO_INVARIANT = :count_iszero_preserved`, i.e.
  `count(iszero, y_out) == count(iszero, y)` — "alpha introduces no NEW zero".

```julia
function alpha_segregate(x, y, M, α; b)
    @assert b > 0 "background floor must be strictly positive (else _exclude_zero deletes pixels)"
    removed_px = α .* max.(y .- b, 0.0) .* M          # α = 0 => exactly 0.0, elementwise
    y_in       = y .- removed_px                       # α = 0 => y .- 0.0 == y BITWISE
    S_out      = sum(y[.!M]); @assert S_out > 0
    boost      = 1.0 + sum(removed_px) / S_out         # α = 0 => exactly 1.0
    y_out      = ifelse.(M, y_in, y .* boost)          # α = 0 => y .* 1.0 == y BITWISE
    return y_out
end
```
