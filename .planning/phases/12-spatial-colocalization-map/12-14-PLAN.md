<objective>
Build the one training surface every later Phase-12 plan uses, and make the two things that silently
destroy an amortized calibration claim — a leaked standardizer and an out-of-distribution held-out
encoding — impossible rather than merely discouraged.

Purpose: 12-15 trains three arms, 12-17 trains two at full scale, and 12-16/12-18/12-19/12-20 all read
those bundles. If each of those plans wires its own training loop, the arms stop being comparable and
the D-10 matched-ablation claim collapses — a coverage difference could come from a different split, a
refit transform, or a different masking rate. This plan makes the arm a keyword argument and everything
else identical by construction.
Output: `train_p12_npe.jl`, its test, and a saved bundle schema the rest of the phase reads.
**On the PROCEED path this plan trains only a 1-epoch smoke net — the real spend belongs to 12-15 and
12-17.** Task 3 is the one exception and it fires only on a Stage-1 DESCOPE, where it trains the
`arm = :none` ablation at spike scale because 12-11 routes D-13's fallback through this plan and nothing
else on that route trains anything.
</objective>

**A CORRECTION TO 12-09's PARENTHETICAL, MADE DELIBERATELY AND RECORDED.** `12-09-PLAN.md:69` says the
MCAR masking is applied by this trainer "to the standardized input". That is wrong and this plan does
not follow it. Masking must happen on the **RAW** 128 rows, before `zt`, because the whole point of
Pitfall 4 is that a held-out region look exactly like a region `correlation()` could not score. A
naturally-unusable patch reaches the net as raw value `0.0` with mask `0`, which after per-row
z-scoring becomes `(0 - mu_r)/sd_r` — **not** zero. Masking after standardization would instead place
the row *mean* at the held-out region, so the net would read "this region is perfectly average" where
inference time says "this region is absent". D-09's own construction in `12-RESEARCH.md` § "The
leave-region-out predictive construction" confirms the raw ordering: it masks `Z_full`, which is
`encode_d01(patch_summary(mci))`, i.e. raw. Record this correction in the file header and in the plan
summary; it is a deviation from a sibling plan's prose, not from any decision.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| train split → validation/test split | A transform fit on all data leaks the evaluation set into the net and inflates every downstream calibration number |
| training-time encoding → inference-time encoding | A held-out region encoded differently at read time measures out-of-distribution behaviour, not borrowing strength |
| Stage-1 gate → training spend | A spend that starts before the verdict makes D-12's "descope before the cost is sunk" unenforceable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
