**The θ assembly lives HERE and nowhere else.** `p12_architecture.jl` (12-04) owns the row *layout*
(`P12_THETA_ROWS`, `p12_theta_index`, `p12_row_c0`, `p12_rows_dev`, `p12_rows_nuisance`, `p12_row_r1`);
`p12_prior.jl` (12-07) owns the *draw*; this file is the only one that includes both, so it is the only
one that turns a draw into a column of a θ matrix. Do not add a second assembler anywhere.

**EACH SAMPLE IS A PAIR: a sample field AND an independent control field (Δρ decision, 2026-07-28).**
`Δρ` in this milestone is `ρ(img) − ρ(control)` (`infer.jl:107`), so a pool that stores one field per
dataset cannot supply a per-region Δρ\* ground truth and 12-18's SBC would have nothing to rank. Draw the
control field from the **same prior at the same r₁** through an independent RNG sub-stream, and store
`z_field_control` / `rho_field_control` / `mu_field_control` beside the sample's. The generative order is
unchanged: r₁ first, then BOTH fields conditional on it. Store the derived
`rho_field_delta = rho_field - rho_field_control` too — it is the deliverable's units and D-07's per-region
Δρ truth — but note it is a *derived* array, not a θ row, exactly as `rho_field` is.

**The rows are the GAUSSIAN field's DCT coefficients (R-2), not the ρ field's.** `p12_dct_vec(vec(z_field))`
reordered by `p12_dct_order`, so row 1 is the DC coefficient `c₀` and rows 2..64 are the deviations in the
frozen smoothness order. In Gaussian space there are no `ghat` atoms; in ρ space there are 6.79 % per
region. The ρ field is stored too — it is the deliverable's units and 12-19 needs it — but it is not a θ row.

**Pitfall 4 is a datagen concern, not a training-loop concern.** The MCAR region masking
(`augment_mask!`, `P12_MASK_K_SET`) is applied by the **trainer** (12-14), not here: this file stores the
raw, unmasked 128 rows so the same pool can serve the masked and unmasked arms. Record the realized
masking rate at training time, not at generation time.

**The trainer masks the RAW rows, BEFORE z-scoring — do not write anything to the contrary into this
file's comments.** An earlier draft of this plan said the masking is applied "to the standardized
input"; that was wrong and 12-14 carries the full argument. In short: a patch `correlation()` cannot
score reaches the net as raw `0.0` with mask `0`, which after per-row z-scoring becomes
`(0 - mu_r)/sd_r`, **not** zero. Masking after standardization would place the row *mean* at a held-out
region, so the net would read "perfectly average" where inference time means "absent", and D-09 would
measure out-of-distribution behaviour instead of borrowing strength. D-09's own construction in
`12-RESEARCH.md` masks `encode_d01` output, i.e. raw. This matters here because Task 1's header block is
exactly where a wrong ordering would get enshrined as a code comment two waves before 12-14 runs.
