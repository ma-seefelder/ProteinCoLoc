AGPL header matching its `spike/simulator/` neighbours, `using LinearAlgebra` and `using SparseArrays`

Header comment must state, in the `prior.jl:21-32` voice: this file is the lattice prior's arithmetic
only; it draws no θ and knows nothing about ρ (that is `p12_prior.jl`'s job); the column-major
indexing contract is inherited from `encode_d01` and must never be transposed; and the per-cell
rescale is not an optimisation but the step that makes D-05's marginal-preservation claim true.

Provide:

`p12_idx(i, j; G = P12_G) = (j - 1) * G + i` — with a comment naming `src/amortized/summary.jl:72-76`
as the reason.

`lattice_adjacency(G)` — 4-neighbour `spzeros(Float64, G*G, G*G)` built with `p12_idx`.

`car_sigma(G, α)` — `W = lattice_adjacency(G)`, `D = Diagonal(vec(sum(W; dims=2)))`,
`Σ = inv(Symmetric(Matrix(D - α*W)))`, returned `Symmetric`. Guard `0 ≤ α < 1` with an
`ArgumentError` in the `spike/npe/architecture.jl:92-99` guard style. Record in the comment that the
degree matrix is NOT a multiple of `I` (boundary cells have degree 2 or 3), which is why the marginal
variances are non-uniform and why the DCT diagonalizes `Q` exactly only in the α → 1 limit.

`gp_sigma(G, ℓ; jitter = P12_GP_JITTER, kernel = :matern32)` — lattice coordinates in the SAME
column-major order as `p12_idx` (`P = [(float(i), float(j)) for j in 1:G for i in 1:G]`). Default
kernel is **Matérn ν = 3/2**, not squared-exponential: the SE kernel reaches `cond(K) = 5.5e9` at
ℓ = 8, and Matérn-3/2 is far better conditioned at the same effective range. Keep `:se` as a named
alternative kernel symbol so the mini-spike can report both, but default to `:matern32`. `jitter` is
PRE-REGISTERED in `p12_consts.jl` — do not tune it after a failed Cholesky; if Cholesky fails, throw
with the failing (ℓ, kernel, jitter) in the message.

`field_sampler(Σ)` — returns a closure `rng -> (L * randn(rng, n)) ./ sd` where `sd = sqrt.(diag(Σ))`
and `L = cholesky(Σ + 1e-12I).L`. This is THE step that makes D-05 correct: `Σ` does not have a unit
diagonal (measured marginal sd 0.658 at an edge vs 0.992 in the interior at α = 0.95), and without
the rescale the copula's per-region marginal is wrong at the boundary and the prior on ρ becomes
position-dependent — the same radial/edge artifact class this phase exists to guard against. Say that
in the comment.

`induced_lag1(Σ)` — the mean Pearson correlation over all 4-neighbour pairs of the RESCALED
covariance, i.e. of `Σ ./ (sd * sd')`. This is the single quantity both arms are addressed by.

`car_alpha_for_r1(r1; G = P12_G)` and `gp_ell_for_r1(r1; G = P12_G, kernel = :matern32)` — bisection
on `induced_lag1` over `P12_CAR_ALPHA_BRACKET` / `P12_GP_ELL_BRACKET` to `P12_R1_SOLVE_TOL`. Both
must be monotone in their bracket; assert monotonicity of the bracket endpoints on entry and throw a
clear `ArgumentError` if the requested `r1` is outside the achievable range. Provide
`lattice_sigma(arm::Symbol, r1; G = P12_G)` dispatching `:car` / `:gp` / `:none`, where `:none` (or
`r1 == P12_ABLATION_R1`) returns `Symmetric(Matrix(1.0I, G*G, G*G))` — the D-10 matched-ablation
covariance, so the ablation is a genuine draw from an independent field and not a special case bolted
on later.

`p12_dct_matrix(G)` — the orthonormal 1-D DCT-II matrix
`C[p+1, i] = c_p * cos(π * p * (i - 0.5) / G)` with `c_0 = sqrt(1/G)`, `c_p = sqrt(2/G)` for p ≥ 1, so
`C' * C == I` to float tolerance. `p12_dct(F)` = `C * F * C'` on a G×G matrix, `p12_idct(Ĉ)` =
`C' * Ĉ * C`. `p12_dct_vec(z)` / `p12_idct_vec(c)` operating on the column-major 64-vector, and
`p12_dct_order(G)` returning the flat index permutation that sorts the G² coefficients by smoothness
(ascending `p + q`, ties by `p² + q²` then by index) so that "the first K modes" is a defined,
frozen ordering and the DC coefficient `c₀` is always index 1. Record in the comment: because the DCT
is orthonormal and exactly invertible, ranking a DCT coefficient IS ranking a sampled parameter, so
D-07's prohibition (which is about LOSSY transforms — the `ghat` clamp, a cell mean) is not engaged;
and "high rank" (D-04) therefore means simply `K = G² - 1 = 63`.

`radial_basis(G)` — the `[1, radius]` design matrix over lattice cell centres (radius measured from
`((G+1)/2, (G+1)/2)`), used by the S-4 radial-energy guard. Put it here so the guard runner does not
re-derive the geometry.

Every function takes `G` as an argument or keyword defaulting to `P12_G`; nothing hard-codes 8 in a
body.
