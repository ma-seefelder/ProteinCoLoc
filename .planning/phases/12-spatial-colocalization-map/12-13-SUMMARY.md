# 12-13 — D-08 correlation-length identifiability: MEASURED, and the answer is NEGATIVE

**The correlation length r₁ is NOT identifiable from the 128-row patch-correlation summary**, and the
probe was strong enough that this is a statement about the physics rather than about the probe.
The measurement **gates nothing**. It appends no Tier-2 constant and moves no threshold.

## The numbers, re-derived by loading the `.jld2`

| Quantity | Value |
|---|---|
| `ratio_raw` (128 raw rows) | **1.00225** |
| `ratio_with_moran` (**PRIMARY**, + Moran's I) | **0.99737** |
| `control_c0_ratio` | **0.29232** — **LIVE** |
| `ridge_residual_shrinkage` (primary arm) | **1.00655** vs the 0.90 floor ⇒ **`vacuous = true`** |
| `ridge_residual_shrinkage` (raw arm) | 1.01148 ⇒ `vacuous = true` |
| `n_total` / `n_fit` / `n_val` / `n_test` | 25 000 / 15 000 / 3 750 / 6 250 |
| selected ridge penalty (both arms) | 1000.0 — the **largest** on the grid, chosen on validation |
| `elapsed_min` | 10.16 |
| pool | `24391320…e336`, `arm = :car`, imsize pinned `(512, 512)`, r₁ **DRAWN** |

Moran's I summary: mean 0.38115, sd 0.14586, range [−0.20127, 0.83526], **0 NaN-imputed**, and its
raw correlation with r₁ is **0.10865**.

## The reading, under the rules fixed before the numbers were seen

**The control is live**, so the null is informative. `control_c0_ratio = 0.29232` is a 71 % error
reduction on the global term through the *same* pipeline, the same split and the same penalty grid.
It is the same order as Phase 11's global analogue (0.157) without matching it, which is expected:
c₀ here is one DCT coefficient of a spatial field at a pinned 512², not a scalar ρ_true. The first
interpretation rule — *if the control is not comfortably below 1.0, both arms are uninformative* —
therefore does not fire.

**`ratio_with_moran ≈ 1.0` with a live control ⇒ r₁ is VACUOUS.** The three consequences the plan
fixed in advance, recorded here:

1. **D-08's hedge is resolved in the NEGATIVE and must be stated as a named limit.** r₁ joins the
   vacuous-nuisance-column limit alongside chromatic ε (12-06, `ridge_residual_shrinkage = 0.96870`).
   Note the ordering: **ε is the better-identified of the two** — 0.969 against r₁'s 1.007 — and ε
   was already pre-registered-vacuous. r₁ is not merely vacuous, it is *slightly worse than the
   prior mean*.
2. **Any widening of r₁'s posterior in 12-18 must be reported as `shrinkage ≈ 1.0`** — a posterior
   no narrower than the prior — and must **NOT** be described as "alive and used". That is the exact
   Phase-11 sentence this plan exists to prevent. **No support-bound ratio may be quoted against it**:
   r₁ is inferred, not conditioned, so `P12_R1_MAX / P12_R1_MIN = 19.0` is a ratio of prior SUPPORT
   BOUNDS and is not commensurable with a posterior width. That constant appears nowhere in the code
   and nowhere in the artifact; it is recorded in the runner's header as WITHDRAWN, with the reason.
3. **The self-confirming-calibration argument behind D-08 still stands on its own.** Inferring an
   unidentified smoothness is still preferable to fixing it wrongly — an inferred-but-unidentified r₁
   returns its prior and propagates that uncertainty honestly, whereas a *fixed* r₁ would assert a
   smoothness the data cannot support. The manuscript should say precisely that, and should not use
   this result to argue for conditioning on r₁ instead.

**The paired reading against 12-18's `shrinkage`, stated now so the comparison is not made
post hoc.** This plan measures `ridge_residual_shrinkage = residual_sd / prior_sd` for a LINEAR POINT
PREDICTOR. 12-18 will measure `shrinkage = post_sd / prior_sd` for a NEURAL FLOW's posterior. Under
the four-branch rule fixed at `12-13:131-152`:

- **both near 1.0 ⇒ CORROBORATION.** The expected outcome. Two different estimators agreeing that the
  image contributed nothing; the named limit is written with both numbers quoted.
- **ridge ≈ 1.0 but posterior well below 1 ⇒ DO NOT claim identifiability on the posterior alone.**
  The flow would be asserting information a linear probe cannot find, which is either genuine
  nonlinear structure or a posterior-WIDTH defect — and width is exactly what has misbehaved here
  before (Phase 11: coverage 0.723–0.767 against a nominal 0.90, intervals ~40 % too narrow, which a
  linear probe would not have shown). Requires r₁'s calibration reading from 12-18 first.
- **ridge < 1 but posterior ≈ 1.0 ⇒ a CAPACITY limitation, not a physical one**, and D-08's hedge
  would then be UNRESOLVED rather than negative. This branch is **ruled out by this run**: the ridge
  is not below 1.
- **A disagreement is a FINDING and is reported as one.** Never averaged, never reconciled.

## Two findings the plan did not anticipate

### 1. Moran's I *does* carry r₁ information — and the ridge still cannot use it

`corr(Moran's I, r₁) = 0.10865` is small but not zero, and it is the right sign. Adding the
statistic moves the ratio from 1.00225 to 0.99737 — i.e. it converts a *negative* result into a
0.26 % error reduction. So the second-order structure is not absent from the summary; it is present
at an amplitude a 129-predictor linear map cannot convert into useful prediction. Both arms selected
`penalty = 1000.0`, the **largest value on the grid**, which is the estimator itself reporting that
almost all of its coefficients are noise. This is the sharpest available statement of the result:
**not "r₁ leaves no trace", but "r₁'s trace is far below the noise floor of this summary."**

### 2. THE PER-BIN TABLE CANNOT SHOW THE PITFALL-2 GRADIENT, AND ITS SHAPE IS A BASELINE ARTIFACT

The plan expected "a strong per-bin gradient (recoverable at short r₁, vacuous at long r₁)" as the
Pitfall-2 shape, to be reported rather than averaged away. **That shape cannot appear in this table,
for a reason in the metric rather than in the physics**, and reporting the table as an identifiability
gradient would be wrong:

| r₁ bin | n | prior RMSE | `raw` ratio | `with_moran` ratio |
|---|---|---|---|---|
| [0.050, 0.229) | 1277 | 0.362869 | 1.00026 | 0.96073 |
| [0.229, 0.409) | 1179 | 0.186830 | 1.00889 | 1.01963 |
| [0.409, 0.586) | 1251 | **0.051422** | 1.03983 | **1.17312** |
| [0.586, 0.769) | 1262 | 0.187374 | 1.00099 | 0.96782 |
| [0.769, 0.950) | 1280 | 0.366287 | 1.00223 | 1.03057 |

The denominator is the RMSE of the **global** fit-split prior mean (0.49829) *within each bin*, so it
is essentially the bin's distance from that mean. Measured: the correlation between
`|bin midpoint − prior mean|` and the reported prior RMSE is **0.99682**, and the central bin's
midpoint sits 0.0006 from the prior mean. **In the central bin the baseline is near-perfect by
construction**, so any estimator must lose there, and the 1.17 is a property of the binning, not of
r₁ at 0.5. The V-shape (0.363 / 0.187 / 0.051 / 0.187 / 0.366) is that distance, not a physical
contrast.

This is inherited from the analog: `run_p12_eps_ridge.jl` bins by `|rho|`, where the target and the
binning variable are *different*, so the denominator does not collapse. Here the binning variable IS
the target. **A per-bin identifiability curve would need a within-bin baseline** (each bin's own
mean) rather than the global one. Not changed here — the plan specified the global baseline, the
headline result does not depend on it, and re-specifying a reported metric after seeing its output is
the move this phase is careful about. **Recorded so 12-18 and the phase report do not read the
central bin as a physical statement.**

## RECONCILIATION — this result and Stage-1 are NOT in tension, and must not be read as if they were

Phase 12 now holds two true results that a reader meeting them in the wrong order will take as a
contradiction:

- **Stage-1 (12-11): spatial borrowing WORKS.** Neighbouring regions inform a held-out region,
  monotonically in r₁, with the crossing where the other 63 regions beat a region's own measurement
  at r₁ = 0.75.
- **12-13 (this plan): r₁ itself is NOT identifiable** — 1.00655, vacuous, and worse than chromatic
  ε at 0.96870, i.e. very slightly worse than the prior mean.

**The correct statement is that the map BENEFITS from spatial structure even though the smoothness
hyperparameter governing that structure cannot be recovered from this summary.** Those are
compatible, and routinely so: one can marginalise over a hyperparameter one cannot pin down. The
borrowing gain is a property of the *field*, measured directly at every rung of the ladder; r₁'s
identifiability is a property of *what the 128-row summary retains about that field's smoothness*.
Nothing in D-08 requires r₁ to be recoverable for the borrowing to be real, and Stage-1 measured the
borrowing without ever estimating r₁ — its ladder **pins** r₁ rather than inferring it.

**This does NOT say the spatial model is unidentifiable.** That inference is the misreading this
section exists to prevent, and it should be stated in the phase report rather than left for a reader
to assemble.

### The consequence that follows, MEASURED rather than assumed: the deliverable inherits a prior choice

If r₁'s posterior is essentially its prior, then the per-region uncertainty the phase delivers is an
**average over `P12_R1_PRIOR = Uniform(0.05, 0.95)`** — a Tier-1 constant confirmed on the
understanding that a uniform is the honest default given no prior belief. So: is the delivered
uncertainty materially sensitive to that choice?

**Yes, materially — and the answer is already in the Stage-1 artifact, so no new campaign was run.**
Read off `p12_stage1_report.jld2`'s pinned-r₁ ladder, which is exactly the sensitivity curve this
question needs:

| r₁ | per-region `ratio_mean` (neighbours only) | full-128 control |
|---|---|---|
| 0.05 | 0.92557 | 0.73188 |
| 0.25 | 0.84660 | 0.67740 |
| 0.50 | 0.71870 | 0.59827 |
| 0.75 | 0.56184 | 0.49659 |
| 0.95 | 0.33569 | 0.32369 |

- Across the prior's support, per-region recoverability varies by a factor of **2.757**
  (0.3357 → 0.9256).
- Marginalised over the actual prior: **E[ratio_mean | r₁ ~ U(0.05, 0.95)] = 0.69189**.
- Under a prior concentrated on the **low** half, U(0.05, 0.50): **0.82862**.
  Under the **high** half, U(0.50, 0.95): **0.55515**. A factor of **1.49** between them.
- This is **not a normalisation artifact**: `baseline_rmse_mean` is flat at ≈ 1.0 across every rung
  (0.998 / 0.996 / 0.990 / 0.980 / 0.998), so the denominator is constant and it is the *achieved*
  error that moves.

**NAMED LIMIT (new, belongs beside the others).** Because r₁ is unidentified, the per-region
uncertainty this phase reports is a **marginal over the assumed r₁ prior**, and that marginal shifts
by ~1.5× between a low-smoothness and a high-smoothness prior over the same support. A user who
believes their biology is smoother (or rougher) than `Uniform(0.05, 0.95)` implies should expect
materially different per-region intervals. The honest framing is that the uniform is a deliberate
no-prior-belief default, not a neutral one — there is no neutral choice here, and the delivered
interval width depends on it.

**Two caveats on the strength of this evidence, stated rather than glossed.** (i) The ladder is a
**ridge**, not the trained net's posterior, so these are recoverability ratios and not posterior
widths — they bound what any linear estimator achieves, and the net's own per-region interval widths
are 12-18's measurement. (ii) The five rungs are **common-random-number paired** by construction
(`run_p12_stage1_ridge.jl:82-87`), so they are not five independent experiments; that makes the
*trend* more reliable, not less, but the spread should not be read as five independent samples.
**12-18 should confirm this on the net's own coverage, and the phase report should carry the limit
either way.**

**Moran's I was validated against three analytic cases before use**, since a wrong implementation
would have produced a null that looked like physics: **+0.857** on a smooth ramp, **−0.0151** over
400 iid draws against the theoretical −1/(n−1) = −0.0159, and **exactly −1.0** on a checkerboard. The
masked-region handling was shown to change the answer (0.8292 with masking honoured vs 0.7848 with
masked entries counted), so a stored zero cannot masquerade as a region sitting at the mean; and
degenerate inputs return `NaN`, never a `0.0` that would read as a measurement.
